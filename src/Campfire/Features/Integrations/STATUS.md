# Integrations implementation and verification

Latest write-path change (2026-10-05): worker maintenance and reservation are one ordered Lua call. It renews the lease, reclaims this worker's unresolved reservation, conditionally replays held jobs, recovers expired workers, promotes due jobs, then reserves. Errors stop the suffix; transport never replays uncertain writes. Heartbeats and acknowledgement remain separate. The real Redis suite passes future/due scheduling, live/expired-worker ownership, wrong-type maintenance failure/recovery and single handling after repair. This is local JIT evidence; final JIT/AOT image and throughput evidence is recorded separately by the parent. The older paragraph below saying worker maintenance is unchanged describes the earlier enqueue-only change.

Implemented:

- Redis-backed independent `Bot::WebhookJob` and `Room::PushMessageJob`, plus registered identity and Active Storage jobs. Enqueue uses the original Resque ready-list name and ActiveJob `JobWrapper`/GlobalID argument format; existing Rails jobs can be consumed. Reservations have renewable leases, abandoned-worker recovery, retry schedules and retained failure records. Analyze/Mirror/Transform/Preview retry integrity errors ten times with polynomial delay/jitter; Purge retries SQLite busy/deadlock failures. Missing media records are discarded. Preview jobs enqueue separate transform jobs.
- Outbound delivery defaults to enabled, matching normal Rails operation. Explicit `CAMPFIRE_DELIVER_INTEGRATIONS=false` holds outbound jobs in Redis while internal jobs continue. All disposable benchmark/test fixtures set false and delete seeded webhook/push destinations. Enabling delivery replays held work. Without Redis the explicit development fallback is an in-memory queue and is not durable.
- Separate bot selection for direct rooms and valid signed mentions, active membership and sender exclusion. Payload plain text uses filename fallback for attachment-only messages and original recipient-name removal. Webhook replies use the complete Rails MIME registry; any content type can become an attachment, including unsuccessful HTTP statuses. Text/plain and text/html replies require200 and are sanitized. Attachment and reply-message SQLite/FTS/unread side effects are transactional, then eager media/broadcast/push apply without recursively notifying bots.
- Administrator webhook URLs deliberately allow private/local services and the normal environment proxy, without automatic redirects. Connection/header budget is seven seconds; reply body reads have seven-second idle timeouts and no artificial body-size ceiling. Public unfurl and push endpoints use a distinct guarded-IP policy.
- Web Push uses actual P-256 ECDH, HKDF, AES-GCM and ES256 VAPID. The pinned gem's exact record header and `2,0` plaintext padding are preserved; ciphertext limit4096 means maximum4078 UTF-8 payload bytes. VAPID audience omits port, authorization uses `,k=`, TTL is28 days and urgency high. The50-slot pool captures badge at notification construction. Only410 and pooled crypto/TLS failures invalidate subscriptions;404 remains. Direct test delivery redirects after success/guarded no-op and exposes actual provider exceptions.
- Push registration accepts JSON/form values, keeps the original permissive key validation and endpoint userinfo/fragment shape, and scopes list/delete/test to the current user. Index uses the original list/control classes, icons and browser/version/platform metadata with the shared Campfire layout. Registration is not proof that deliberately invalid keys can deliver.
- `/unfurl_link` preserves original supplied/fallback/canonical/image URL strings, whole-URL case-sensitive media filtering, Twitter/X rewrite, first-public-address selection and redirect rechecks. Fetches have60-second connect/header/idle phases, five MiB cap and ten absolute redirects; no12-second whole-operation limit. Raster preview HEAD uses raw content type. HTML meta encoding and original ASCII sanitization for binary documents without meta encoding are implemented.
- Typed source-generated JSON, JsonElement/JsonNode and AOT-compatible SQL materialization cover the feature. No runtime JSON reflection or external WebPush package is required.

Write-path optimization: durable enqueue now uses one Lua invocation for original `SADD resque:queues default` followed by `RPUSH resque:queue:default payload`. Original ready-list/wrapper bytes and durable ownership remain unchanged; registration failure stops before list insertion. A real Redis wrong-type regression verifies no job is appended when queue registration fails. No uncertain-delivery retry is added. Worker lease/recovery/held-job maintenance is unchanged. Fresh optimized JIT/Native AOT images execute the later enqueue/publication paths successfully during27 shared Redis controls and57 media requests; exact identities are in optimized-verified.json. Performance remains the parent benchmark task.

Actual limitations/differences:

- Original ready-job and Cable wire formats are interoperable; custom reliable reservations, held lists and delayed retry state require a .NET worker. Rails Resque workers do not consume the custom scheduled set. Processing is at least once, so worker loss/uncertain acknowledgements may repeat side effects. No exactly-once claim is made.
- The room job awaits pooled delivery before acknowledgement instead of returning after enqueue to Rails' volatile pool (50 workers,10000 pending limit). This gives the durable job ownership of delivery; the original volatile-pool rejection boundary is not reproduced.
- Push/public-document HTTP clients avoid environment proxies to preserve checked-IP pinning. Webhook proxies are allowed. The webhook initial seven-second header budget includes connection time, whereas Ruby treats open/read phases separately. Push has a60-second overall HTTP budget; exact slow-provider phase timing is not certified.
- VAPID configuration uses environment variables; original encrypted Rails credentials fallback is not implemented. Tests verify real cryptography locally, not interoperability with an actual browser/vendor.
- The meta-encoding implementation is checked against pinned Nokogiri examples; every malformed HTML/encoding and every legacy UserAgent parser branch has not been differentially exercised.
- Latest-image Native AOT, original Rails/.NET mixed Redis and full codec/provider matrices require their separately recorded live probes. Passing local JIT suites is not presented as native or external delivery evidence.
