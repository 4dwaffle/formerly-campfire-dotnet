# Chat and presentation status

The port implements the concrete room/open/closed/direct, membership/involvement, message/boost, search/autocomplete, welcome/sidebar and bot API actions from pinned Rails `6c7f8fa15f8c39478af64a483dcdf6223527ed22`. Business rules and rendering were traced through Ruby models/controllers/helpers/ERB. Reference checkouts remain read-only. SQL is parameterized and has concrete Dapper AOT interception; HTTP JSON has explicit source-generated metadata.

The [original audit](../../../../bench/parity/chat/report.md) and raw evidence remain intact. The [remediation report](../../../../bench/parity/chat/remediation.md) maps C01-13 and presentation/source findings to fixes and evidence. This document describes the current implementation rather than the earlier incomplete port.

- Membership scopes every room/message/search/autocomplete operation; private access is not bypassed by administrators. Message changes require creator/admin; boost deletion requires its booster. Direct rooms reuse an exact participant set and cannot convert through shared-room namespaces.
- Message/rich-text/attachment/room changes commit before FTS callbacks, matching controlled Rails fault evidence. Unchanged body/client-ID/attachment assignments preserve timestamps and cached fragments, but still invoke the FTS update callback after commit; changed assignments retain touches and indexing. The controller still broadcasts an unchanged update as Rails does. Create unread handling runs after successful indexing and affects disconnected visible peers except creator. Boost touches also trigger indexing after commit. Invalid attachments still roll back the initial message transaction. Index UPDATE does not invent a missing row.
- Room renames commit before a separate membership revision, as proven through injected SQLite failure. Membership revocations request realtime disconnect. Message/room deletion captures blobs before deletion, then delegates purge to media.
- Safe presentation and editor reconstruction retain supported editor formatting, regenerate attachments/mentions, recover stored legacy User mention identifiers without Marshal deserialization, and restrict preview hosts. Autolinking and solo-unfurl filters follow the pinned helpers. Plaintext, filename indexing, millisecond timestamps and bot body HTML follow their distinct source paths.
- Required objects, raw curl bodies, blank attachment clearing, scoped malformed parameters, format failures and conditional cache handling preserve the tested Rails status/side-effect contracts. Explicit JSON null and an absent body preserve different rich-text row states. Action Text normalization strips Ruby ASCII/NUL outer whitespace while preserving nonbreaking spaces. Message-page weak validators expand ordered model cache keys with the pinned original template digest, flash and frame identity, matching five captured Rails golden vectors. Sidebar Turbo-Frame responses use the minimal original HTML/head/CSRF/body layout; ordinary requests retain the application layout. Parent supplies format suffix/HEAD normalization, browser gating, headers and error documents. Pinned declared settings/direct-show actions without actual implementation retain their failures rather than claiming successful functionality.
- Original DOM controllers/actions/targets, QR/share/clipboard controls, translations, loading/alert notification markup and generated original browser/system/install guidance are present. Sidebar and direct room labels follow original viewer rules and association order. Shared Cable HTML omits the publishing request's CSRF fields.
- Malformed room identifiers follow the original redirect/alert path after Rails-style casting. Orphaned creators retain their authorized message row and original failed-content fallback; administrators can still edit its body. Search with no reachable return room retains the original footer failure. MessagesController show/edit preserve the full application layout despite Turbo-Frame requests, because only its index disables the layout.
- A bounded 32 MiB generic message-fragment cache retains no request CSRF fields. Its default HTML policy now follows pinned Rails `[message, "presentation-v3"]`: message ID/version plus origin for URL safety. String rendering, UTF-8 HTTP segments and Cable share one cache. Warm HTML room/message/search/show/refresh selections fetch only authorized message columns; there are no body/boost/blob dependency or all-user fingerprint queries. Misses batch hydrate presentation rows/boosts in a SQLite read snapshot. Creator/avatar/mention/room/raw-body changes intentionally leave an existing fragment stale until the message is touched or evicted, matching independently captured production Redis-cache behavior. API edits and boost mutations touch the message. Editing and bot JSON stay fully hydrated. Permission queries run before lookup and again during hydration; they are never cached. Precomputed UTF-8 form offsets insert fresh request CSRF bytes. The budget counts all retained string keys, encoded bytes, offsets and conservative object overhead. Oversized keys are rejected, unused attachment metadata is not retained, and no independent time expiry is introduced. Sanitizers are exclusively borrowed from a bounded pool, with concurrent safety tests.
- HTTP message creation awaits the asynchronous writer lease. Its initial transaction commits before FTS and unread callbacks run as separate autocommits on the same leased connection; indexing failure preserves the committed message and stops unread handling. Cancellation while awaiting/preparing a commit prevents it; committed callbacks complete without cancellation checks. Realtime/integration work occurs after the lease has been released.
- All 314 compiled logical assets match the original pinned Rails image SHA-256 bytes; parent imported the original assets. No fixture response shortcut or runtime dependency on reference checkout templates is used.

## Limits

**Known unresolved storage parity:** the latest frozen hotpath image probe finds 12 exact-body failures (six per .NET executable) for human/bot NBSP, CR/CRLF and numeric-entity inputs. Rails stores `&nbsp;`, normalizes CR to LF and resolves the numeric entity; .NET retains the input spelling. All status/FTS/plaintext/render-presence checks pass, but the [focused POST gate](../../../../bench/parity/chat/post-assertions-hotpath.json) is 98/110. [Latest selected verification](../../../../bench/parity/chat/hotpath-validation.md) is 304/316 with the gap preserved, not universal parity. The frozen source was intentionally left unchanged in this validation phase.

The frozen `rust-inspired-jit`/`rust-inspired-aot` snapshot (`7702ad59794a99f7853827b97ae49924c71e0d9cdf20d1ff5f29a22a059b6ee5`) passes **336/336 live checks**: 223 standard comparisons, 47 original cache/no-op comparisons and 66 actual gzip/CSRF checks. [Portable verification](../../../../bench/parity/chat/verification-rust-inspired.json) derives **852 response captures** (284 per application) from saved records and includes exact image IDs and checksums. Gzip bodies decompress successfully, preserve warm/identity message IDs and declared wire lengths, respect zero gzip quality, retain fresh metadata/composer tokens, reject another user's token without persisting a boost and accept the current user's token with a real persisted boost. HTTP cannot expose internal fragment provenance; the typed flag/slice guarantees remain local test evidence. Later parent host conditional-header and codec changes are outside this frozen snapshot. [Cleanup](../../../../bench/parity/chat/cleanup-rust-inspired.json) confirms zero remaining owned containers, volumes or networks; historical failed captures remain unchanged.

No assertion of universal or byte-for-byte Rails parity is made. The message-page template digest is generated from the pinned Rails views and must be regenerated when updating that view revision. .NET HtmlSanitizer/AngleSharp replace Loofah/Action Text; every malformed HTML serialization and autolink edge is not exhaustively verified. Hostile editor markup removal is tested, but browser execution of the original hostile fixture is unverified. Mobile/offline/PWA permission states and concurrent refresh/unread/reconnect races need broader browser/concurrency coverage. Shared storage/realtime/integrations behavior and deployment prerequisites are documented by their respective owners.
