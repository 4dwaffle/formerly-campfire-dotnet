Operational limits: optional native processors are required for their respective representations; absent tools leave those blobs unrepresentable and do not invent generated bytes. PDF previewability checks the original cached Poppler/MuPDF availability commands; default Docker images omit both to match pinned Rails, while installations may configure `CAMPFIRE_PDFTOPPM_COMMAND`/`CAMPFIRE_MUTOOL_COMMAND`. The helper's loader blocking is active only when `CAMPFIRE_VIPS_COMMAND` points to it. Native analysis/processing has30/45-second cancellation budgets that Rails subprocesses do not impose. Animated multipage and every installed libvips codec/operation have not been exhaustively tested; Ruby image_processing composite/metadata helper methods are not fully reproduced by generic CLI dispatch. Storage supports the configured local disk service; S3/GCS/Azure/mirror service configurations are outside pinned deployment. No periodic orphan-blob sweep is added because pinned Campfire has none. File locks coordinate hosts sharing a filesystem; separate storage replicas would need a storage architecture beyond pinned local disk. Owner commit followed by disk-publication failure retains the pending bytes for retry, but a process loss between those phases has no automatic pending-file finalizer. New keys use32 hexadecimal characters rather than Rails'28-character base36 token; both use the same compatible disk sharding/schema.
