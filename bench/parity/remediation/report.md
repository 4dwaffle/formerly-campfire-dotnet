# Campfire port remediation evidence

The original [failing audit](../report.md) is preserved. Its identified identity, chat, framework, assets, realtime, job and media problems have implementations and focused regressions. These checks establish the cases below; they do not certify every Rails behavior or browser state.

## Verified runtime snapshots

The `parity-normal-jit` and `parity-normal-aot` images have immutable IDs recorded in the [chat instance manifest](../chat/instances-final-02.json), [identity report](../identity/remediation.md), and [realtime/media verification](realtime_media/verified.json). Their runtime source hash is `cfb960143f420514d38dee0568954771d6de356f5baea8d52366b49628cd07e5`.

- Chat: 585 actual main/edge/follow-up requests; 154 selected comparisons, 17 source-branch comparisons and 22 frame/validator comparisons passed. Earlier 12 deliberate FTS failure comparisons verified separate after-commit effects. The broader inventory retained four status/layout differences per build; later source fixes require fresh runtime verification.
- Identity/persistence: primary, edge, mutation and framework probes have zero recorded differences on the verified images; signed-cookie reads/writes work in all six Rails/JIT/AOT directions. Pinned Rails `db:prepare` accepts copied fresh port databases without losing seeded rows or inventing pending migrations. See the exact scope and limitations in the identity report.
- Realtime: mixed Rails/JIT/AOT over one shared Redis passes all 27 typing, token-free Turbo and remote-disconnect controls. Removed-message broadcasts use the original UUID after the database row is gone.
- Media: 57 actual requests with zero HTTP errors. All three implementations generate the same actual PNG thumbnail bytes and SHA256; legacy aliases, glob routes, proxy/spoof controls and default PDF preview availability match. The latest omitted-metadata HTTP empty-hash correction requires a fresh runtime control.
- Assets: all 314 pinned paths match byte-for-byte in Rails/JIT/AOT, across 1,884 requests. An independent QR decoder verifies nine short, long and Unicode SVG cases. Online backup/restore uses real SQLite data and FTS integrity checks.

## Performance corrections after those snapshots

The [CPU investigation](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/performance-diagnosis-20261005/report.md) records sanitizer reuse, bounded token-free fragment caching, physical-connection SQLite defaults, Redis connection reuse and reduced copying. The next source changes defer presentation hydration until cache misses, stream UTF-8 fragments with fresh request CSRF, await SQLite writer admission and retain separate committed callbacks under its lease. Redis publication and durable enqueue each use a bounded Lua operation with preserved stop-on-error behavior. They require rebuilt JIT/AOT images before performance or native runtime claims.

The rebuilt `optimized-jit` / `optimized-aot` snapshot has runtime source hash `09944df3706d5c58cdcd0552ae09a5405d48f040d07df68dd3491d0bc67c70de`. Its Release solution build has zero warnings/errors and 85 passing xUnit tests (32 identity, 48 chat, five system). Actual native/JIT runtime [realtime/media verification](realtime_media/optimized-verified.json) passes all 27 mixed Redis controls and nine metadata/signed PUT/PDF controls; 57 media responses have zero HTTP errors and identical actual PNG output. SQL NULL versus HTTP empty-hash metadata is now verified on those images. The publication ACL test preserves the applied prefix and stops before a forbidden command's suffix. Benchmark results for this exact snapshot belong in [its own directory](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/optimized-20261005/report.md).

The additional [cache-policy probe](../chat/cache-assertions-final-04.json) passes 15/20: stale fragments after raw dependency edits now match, but a no-op PATCH reveals different dirty tracking. ## Rust-inspired SQL and rendering snapshots

The initial `rust-inspired-jit` / `rust-inspired-aot` snapshot has runtime source `7702ad59794a99f7853827b97ae49924c71e0d9cdf20d1ff5f29a22a059b6ee5`. It adds bounded prepared SQLite command reuse and request-local query/render preparation. [Chat verification](../chat/verification-rust-inspired.json) passes **336/336** selected checks with **852 actual HTTP captures**: 223 standard/source/frame/FTS comparisons, 47 cache/version/no-op comparisons and 66 compressed-page/fresh-CSRF comparisons. [Identity/framework verification](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/performance-diagnosis-20261005/rust-inspired-identity-method.md) matches 16 identity and 35 framework cases with 186 requests, including an actual application SQL foreign-key fault, rollback and successful recovery. These checks retain their exact initial image IDs.

The first native fragment-gzip implementation produces valid, smaller responses but regresses throughput. Its failed [same-image compression pilot](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/performance-diagnosis-20261005/rust-inspired-phase.md), intermediate allocation probes and native correctness evidence are preserved. Later work removes boxed history comparisons, repeated request-local copy allocations and branch-heavy CRC work, then adds a rolling metadata fingerprint with exact ordered collision checks. The codec remains opt-in; smaller encoded responses alone do not establish faster service.

The final `rust-inspired-v2-jit` / `rust-inspired-v2-aot` snapshot has runtime source `e028436cf93f752167e32c8d666de67cd3170a9cb4a79a6170f0f3172827e89e`; [build identity](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/performance-diagnosis-20261005/rust-inspired-final-build.json) records immutable binaries and zero-warning/error builds. Current local validation passes **311 xUnit cases**: 42 Identity, 55 Chat and 214 System, including 197 native-codec cases. These counts are not 311 independent application flows. A deterministic [test-host disposal correction](https://github.com/4dwaffle/campfire-dotnet/blob/5cdf8ad38543096935b9a98d7443f7aa1a94e93f/bench/results/performance-diagnosis-20261005/rust-inspired-shutdown.md) completes datastore disposal before deleting fixture storage; production persistence was unchanged.

Live compression checks on the initial snapshot exposed an existing validator discrepancy: Rack 3.2.6 compares the entire `If-None-Match` header literally, whereas the port normalized weak validators, lists and wildcards. The final middleware follows the pinned comparison and has five direct regression vectors. Compression negotiation also distinguishes the pinned Thruster proxy from Rack and ASP.NET; those differences remain recorded rather than claiming complete proxy equivalence. Final binary-specific codec controls are recorded separately from the broader initial feature audit.

The final [native codec/runtime proof](../realtime_media/fragment-gzip-live-final-proof.json) records **47 controls and 99 requests** on the actual final JIT/AOT binaries, with native/cache markers, independent gzip decoding, exact whole-body validators, fresh tokens, cross-user rejection and mutation invalidation. Stable manifest responses verify exact weak validators produce 304 while stripped-weak/list/wildcard inputs produce 200; dynamic room wildcard responses now match Rails. Zero 5xx and three expected CSRF 422 responses are recorded. All eleven owned fixture resources were removed. The broader initial feature checks retain their original source scope; the current benchmark does not independently certify every old media/asset/protocol result.

A fresh focused human/bot message POST probe discovers unresolved stored-body serialization differences: Rails serializes nonbreaking spaces as `&nbsp;`, normalizes carriage returns to newlines, and decodes the tested numeric coffee entity, while the port retains those original input forms. The selected status/FTS/render-presence controls pass, but 12 stored-body comparisons fail across JIT/AOT. This is a real existing parity gap; zero benchmark errors do not close it. Frozen application source is preserved, and the failed captures remain available in [Chat's current verification report](../chat/hotpath-validation.md): 304/316 selected checks pass, 12 actual stored-body failures remain. It preserves 546 complete response records, separate initial checker mistakes and seven additional bodies with incomplete headers/status. Cache 47/47, source 17/17, frame 22/22 and extended gzip/session 120/120 pass; all owned fixture resources are removed.

## Remaining limits

Full Rails parity remains unverified. In particular, the reports do not establish exhaustive malformed HTML/autolinking serialization, every mobile/offline/PWA notification state, every concurrent refresh/unread/reconnect or permission-revocation interleaving, all codecs, all external Open Graph servers or actual vendor push delivery. Development-only Action Mailbox conductor UI is not implemented. Native media operational time budgets and the job worker's bounded resource policies are deliberate differences documented in the feature reports. Generic Redis pipelines can apply a suffix after a middle error; application publication uses Lua to preserve its original failure boundary.
