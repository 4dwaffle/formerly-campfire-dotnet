# Warm Chat preparation changes

The later POST preparation change preserves the previously verified callback/cache semantics. `RichText.PlainText` bypasses HTML parsing only when the ASCII/NUL-stripped fragment contains no `<`, `&`, NUL or CR; entities, markup, mentions and CR normalization retain the original parser/reducer. This removes the DOM, traversal collections and node-value dictionary from plain-text indexing while the writer lease is held. Cold message rendering reuses one plaintext conversion for emoji and sound detection rather than converting twice. It still sanitizes presentation HTML separately.

The human Turbo create response rechecks message authorization through metadata and reuses the initial room object, matching pinned `RoomScoped#set_room` and the controller's retained `@room`. Attachment processing touches records but does not reload that room object. Once the preceding broadcast warms a fragment, response preparation requires one Chat query instead of the earlier message graph, boost and room queries (three). Bot creation has no HTML response branch, so this SQL reduction does not apply to bot POST scores. Six new regression cases cover actual indexing/presentation with Unicode, ASCII trimming, CR normalization and entities, plus token-free broadcast/warm-response reuse, fresh per-user CSRF and revoked membership. Release compilation is clean and the full Chat suite passes **61/61** with HTTP JSON reflection disabled. This later source has no new native image or throughput proof yet; the frozen 7702 captures below remain attached to their recorded images.

This source change follows the verified Rails fragment policy and no-op callback behavior. It does not change cache keys or replace request authorization with a permission cache. The earlier executable captures and benchmarks remain attached to their recorded immutable images; this later change has not been benchmarked by the Chat worker.

The Rust comparison used `reference-rust/crates/campfire/src/controllers/rooms.rs::render_show`, `reference-rust/crates/db/src/models/message.rs::paged`, and `reference-rust/crates/views/src/messages.rs::MessageItem`. Rust prepares page inputs in one read scope, checks existence beyond the first 40 rows rather than counting a whole room, and carries immutable cached fragments into response assembly.

The .NET changes are confined to Chat and its tests:

- `ChatStore.RoomPage` authorizes the room and selects its page through one connection. `Page` shares this implementation; around-message selection retains room-scoped timestamp anchors and excludes equal-time peers. Boost loading for hydrated pages is consolidated onto that connection. Each request still performs authorization, and hydration still checks membership again.
- Invitation visibility uses one statement combining the original-room lookup and an `OFFSET 40` existence check. It stops scanning after the first extra page row.
- Application layout account/logo metadata comes from one query, reused only within the current rendering request. Minimal Turbo frames return before unused application-layout account/logo reads. The CSRF/head/body wrapper remains present.
- Sidebar direct participants use one batch query with a small presentation projection. The original participant order, self-only fallback, avatar/name fields and HTML remain unchanged. Placeholder queries and membership/unread reads stay live.
- Four fixed frontend templates resolve static asset URLs once. Rendering computes escaped user/avatar substitutions only when their placeholders are present; Composer and Lightbox no longer sign unused user avatar URLs.
- `RoomContentSegments`, `MessagesContentSegments` and `SearchContentSegments` carry the parent-owned `HtmlSegment` contract. Only immutable cached generic message byte slices are `Cacheable=true`. Shell bytes and fresh per-request CSRF inputs are always false. Existing string and byte-list APIs remain compatible. Warm assembly avoids temporary missing-message lists/dictionaries and a final LINQ copy.

`WarmPreparationTests.cs` wraps **ChatStore read scopes**, rather than instrumenting the whole SQLite engine or auth service. The warm ordinary room test verifies **three scopes**: authorized room/page (two SQL statements), invitation (one), and account/logo (one). This is **four Chat SQL statements**, excluding authentication/session/CSRF reads and cache misses. The old unanchored path made six to eight separate Chat reads/statements depending on invitation visibility. The member sidebar test verifies **five Chat read scopes**, including its two placeholder queries, independent of the number of direct rooms. Minimal-frame layout itself performs zero unused account reads. These counts are source/test evidence, not latency measurements.

The focused regressions verify unchanged presentation ordering/HTML, renewed account metadata on the next request, warm hits without hydration, revocation after a warm page, stable fragment array/slice identity, fresh token isolation and string/segmented output equivalence. The existing cache, no-op update, orphan, permissions, editor, HTTP negotiation and FTS failure regressions also pass. Validation: Release build has **zero warnings/errors**, and the Chat suite passes **55/55 tests** with HTTP JSON reflection disabled. A transient Windows fixture deletion failure during the concurrent Persistence pool change disappeared after that owner's shutdown correction; the complete rerun passed. Native images and final performance measurements remain the parent's responsibility.
